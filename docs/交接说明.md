## 一、这是什么

一个**数字纪念形象**的手机网页（H5 = 用网页技术做的手机页面）。家属扫码进入某个人物的页面，能看到简介，能和"他"聊天——回答由大模型基于**事先逐条审核过的生平资料**、用第一人称生成，可以朗读出来。

页面永久标注"AI 生成"，资料的边界是硬约束：**资料里没写的事，一律说不记得、不知道，不许编。**

## 二、整体目标（三层，从上往下越来越远）

1. **产品层（当前重心）**：做成可重复交付的模板——换一份人物资料就是一个新客户，不改代码。
2. **试点层**：先用虚构人物（林叔、周姨）跑通全链路，再拿**已获家属书面授权**的真实人物做小范围内部试点。
3. **技术层（最终形态）**：完整的语音对话 + 数字人形象。四段链路：**语音识别 → 大模型 → 克隆语音 → 口型驱动**。性格模仿靠提示词 + 语料，不靠训练。

## 六、几条别随手改的设计决定

1. **不用框架、不引第三方 Python 包。** 演示现场最怕装不上、跑不起来。当前机器 C 盘只剩约 12 GB，也吃不下大依赖。
2. **录音在浏览器里直接录成 16kHz 单声道 WAV。** 手机默认录的是压缩格式，转码要 ffmpeg；直接录标准格式就绕开了这个依赖。
3. **密钥只存在于 `server/.env`**，HTTP 永不返回，也不写日志。缺失时所有语音/模型能力自动降级，页面照常可用。
4. **人物资料不审核不能上线。** 内容改一个字摘要就变，必须重审。这条别为省事绕过。
5. **任何外部服务失败都回退，不阻断页面。** 模型挂了给审核过的答案，语音挂了回浏览器朗读。
6. **口型驱动不进这一轮。** 它会把延迟从 2 秒推到十几秒，工程量和硬件要求高一个数量级，必须单独立项验收。

## 九、常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能开，问答一直转圈 | 模型密钥失效或网络不通 | 看 `/api/health` 的 `mode`；`demo` 说明没读到密钥 |
| 点麦克风提示"语音服务未配置" | `NLS_APPKEY`/`NLS_TOKEN` 没填 | 填 `.env` 后重启服务 |
| 手机打不开局域网地址 | 防火墙或不同 Wi-Fi | 防火墙放行 Python 专用网络；确认同一 Wi-Fi |
| 人物在列表里消失了 | 审核记录失效或被停用 | 跑 `manage_profile.py check --all` 看具体原因 |
| `/api/asr` 一直 503，朗读也回退 | 临时 Token 无效或语音服务故障 | 控制台重新取 Token 并更新本机 `.env`；新版会自动重读配置 |
| 公网地址忽然打不开 | 隧道进程停了，或本机关机/休眠/断网 | 重新运行 `scripts/share.ps1`，地址与二维码会自动换新 |
| 公网能开页面但一问就报错 | 链接缺 `k` 口令，或口令与服务端不一致 | 用生成的二维码进入；口令在 `server/.env` 的 `ACCESS_CODE` |
| 手机点录音没反应 | 用 http 地址打开，浏览器禁用麦克风 | 必须 https：局域网自签证书或公网隧道，二者其一 |

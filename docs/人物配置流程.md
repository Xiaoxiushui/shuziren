# 人物配置、审核与发布

所有命令在项目根目录执行。新增人物先进入草稿，不直接复制到 `profiles/`。真实素材的事实和授权由负责人核验；脚本只检查字段、审核完整性和版本一致性，不能证明事实或授权真实有效。

## 1. 建立草稿

```powershell
py -3 scripts/manage_profile.py init --id example-person --kind fictional --name 示例人物
```

真实人物使用 `--kind real`。ID 为 1–48 位小写字母、数字或短横线。已准备空白真实人物模板 `drafts/memorial-template/profile.json`，尚未审核或发布。

编辑 `drafts/example-person/profile.json`，只写允许向访问者展示的已确认资料。必填结构以模板为准，`schemaVersion` 为 1。首页建议问题为 1–6 条，每个问题必须匹配至少一条回答的关键词；回答最多 100 条，单条不超过 500 字。照片、录音、授权原件、私密联系方式等原始素材单独保存，不放入此 JSON。

## 2. 生成逐条审核记录

```powershell
py -3 scripts/manage_profile.py review --draft drafts/example-person
```

生成的 `review.json` 默认全部待审核。审核人逐项核对显示名称、简介、来源说明、语气、习惯、边界、欢迎语、建议问题、回答和回退文案。每条 `items` 填写 `status: "approved"` 和非空 `sourceRef`，例如内部素材编号和页码；未确认内容先从人物资料中移除，不能直接批准。

总记录填写 `status: "approved"`、`reviewer` 和带时区的 ISO 时间 `reviewedAt`（例如 `2026-11-02T10:00:00+08:00`）。真实人物还需 `authorization.status: "confirmed"` 和内部授权记录编号 `authorization.recordRef`；虚构人物保持 `not_required`。不要在引用编号里复制授权正文或敏感证件信息。

`profileDigest` 绑定本次人物资料。只改空白或 JSON 字段顺序不影响摘要；修改内容后必须重新生成清单、重新核验：

```powershell
py -3 scripts/manage_profile.py review --draft drafts/example-person --reset-review
```

旧记录保存在草稿的 `review-history/`，不会自动沿用批准状态。

## 3. 校验并发布

```powershell
py -3 scripts/manage_profile.py check --draft drafts/example-person
py -3 scripts/manage_profile.py publish --draft drafts/example-person
py -3 scripts/manage_profile.py check --all
```

校验不通过则不发布。发布写入 `profiles/<id>.json` 和私有的 `reviews/<id>.json`，版本归档至 `profile-versions/<id>/`。更新已有发布使用 `publish ... --replace`，自动保留前一版。发布写入失败会恢复此前审核记录。

服务每次读取人物都检查审核记录与资料摘要；失配或记录被撤下返回 `503 profile_unavailable`，人物列表不展示该项。前端遇到人物不可用会停止问答；真实人物在无法连接服务确认状态时也停止使用缓存回答。服务器仍可在人物审核有效、模型失败时返回已审核答案。

仅仓库自带的 `lin-shu-demo` 和 `another-demo` 两个虚构样例兼容无审核侧文件；新增人物均需走审核流程。旧的自定义人物需补充版本、类型和对应审核记录。

## 4. 生成链接并交付

```powershell
py -3 scripts/generate_links.py --profile example-person --base-url http://电脑局域网IP:4174/web/ --out out/example-person
py -3 scripts/package_demo.py --profile example-person --out out/example-person.zip
```

把地址中的电脑局域网 IP 换成实际地址。链接和交付包都会先检查人物是否可用。链接清单记录人物摘要，修改发布资料后重新生成。单人物包只包含指定人物和运行所需审核侧文件，不带其他客户人物、草稿、原始证据或历史版本。包内审核侧文件供服务器校验，HTTP 和模型请求均不提供其内容。向交付方移交包意味着移交该审核记录，应使用内部引用编号。

默认不带 `--profile` 的包仅含两位虚构演示人物。单人物包请从根地址人物列表或生成的专属链接进入。

`drafts/`、`reviews/`、`profile-versions/` 已忽略 Git；重要素材和审核记录应另行备份。停用人物可将对应发布文件与审核侧文件移入私有归档，列表和后续请求会立即反映状态；已发送到访问者浏览器的公开资料无法撤回。

# 打包交付

## 生成交付包

在项目根目录执行：

```powershell
py -3 .\scripts\package_demo.py --out out\digital-memorial-demo.zip
```

脚本会打包页面、服务端、人物示例、一键启动文件、脚本、文档和回归检查，并排除 `.git`、`__pycache__`、`.env`、`.env.local`、`.env.production` 等环境配置和历史生成目录。保留空白的 `server/.env.example` 供接收方填写。

默认仅包含仓库的两位虚构人物。单客户使用 `py -3 scripts/package_demo.py --profile 人物ID --out out/客户包.zip`。打包前验证人物结构、审核状态与资料摘要，失败时不生成新包。`PACKAGE-MANIFEST.json` 列出本包人物和文件。

单客户包包含指定的 `profiles/<id>.json` 和运行所需的 `reviews/<id>.json`（如有），不包含其他客户、草稿、原始证据或版本历史。审核记录仅用内部编号引用证据，不写证件正文。HTTP 不开放 `reviews/`。详见《人物配置流程》。

## 交付包验收

1. 将 ZIP 解压到一台没有项目历史文件的新目录。
2. 双击 `一键启动.cmd`，或按包内 README 的 PowerShell 命令启动服务。
3. 打开根地址人物列表和本包人物专属链接；两人物演示包另检查第二个人物。
4. 完成《MVP 验收清单》。
5. 把交付包版本、人物 ID 和验收日期记入客户记录。

开发环境可先运行自动化解压验收：

```powershell
py -3 -m unittest discover -s tests -p "test_*.py" -v
```

该检查使用系统临时目录和独立端口，不读取真实模型配置；会验证交付包中的入口文件、静态页面、人物列表、周姨问答及项目私有文件的 404 边界。本轮 Windows 原生双击和另一台手机实际扫码仍需现场验收。

## 不得打包的内容

- `server/.env` 和任何 API 密钥；
- 未确认的人物素材；
- 临时录音、聊天日志和调试输出；
- 其他客户的人物 JSON。

## 总目标

做一个可以重复交付的**数字纪念形象产品**：家属扫描纪念照片或相框上的二维码，进入专属手机网页，查看人物介绍，和基于已审核生平资料构建的 AI 形象进行文字、语音交流。新增客户主要替换人物资料和资源，不重新开发页面。

完整体验逐步走向：**扫码进入 → 人物展示 → 语音识别 → 基于人物资料的模型回答 → 已授权的复刻声音 → 口型与形象驱动**。同时补齐稳定网址、持续运行和多客户交付能力。性格和表达方式优先通过人物资料、语料和提示词实现，现有计划不要求训练模型。

贯穿各阶段的要求：持续显示 AI 生成标识；不暗示真人意识；回答以审核资料为依据，未知内容应明确说明；真实人物先核验素材与授权；密钥和审核记录保存在服务端。现有回答边界主要依靠提示词和素材约束，历史边界探测通过不代表模型绝不会失真。

## 优先处理的缺口

这些是接手核查发现的现状，本次尚未修改代码。

1. **访问口令与启动入口尚未闭环。** `scripts/launch.py` 的健康检查不带口令，对本机正在运行的服务实测返回 `False`；它会把受保护服务误判为未就绪。`launch.py` 和 `serve.ps1` 生成的局域网入口也未带口令。`web/people.js` 没有像对话页一样读取网址中的 `k`，首次从人物列表进入、且浏览器没有存过口令时会加载失败。现有 59 项自动检查没有覆盖这组新增流程。
2. **语音体验与实测记录需要补齐。** 已有记录指出回答朗读约 30–40 秒、内容偏长；逐句合成会累积多次调用耗时，需要重新记录当前版本的首声延迟、朗读长度和失败恢复。
3. **手机兼容性与故障验收未收口。** 补微信内置浏览器、iPhone Safari 复验、真实 Token 失效后的识别提示和朗读降级；原生双击、另一台手机扫码、实体打印仍要现场验收。
4. **文档状态曾互相冲突。** 旧文档中的“语音从未连通”、旧测试数量和未勾选的阶段清单不能代表当前状态。本报告区分本次检查、历史实测和未来计划；历史过程保留在原记录中。

| 阶段 | 要完成什么 | 完成标准 |

| 本人声音复刻 | 取得授权录音，接入复刻与合成适配，建立人物和音色映射 | 实际听到对应音色，验证听感、时延和失败回退；不是只填写 `voice_id` |
| 正式持续交付 | 固定 HTTPS 域名、在线服务器、访问控制、资料备份与部署说明 | 二维码长期指向同一人物，不依赖演示电脑开机；换设备与重启后仍可访问 |
| 动态数字人 | 独立做口型驱动和形象方案的可行性验证 | 有明确的形象素材、运行资源、同步效果、时延和成本验收结果，再决定投入 |
| 多客户运营 | 按客户隔离资料、记录用量；随后补音色映射、Token 续期、限额及批量建档 | 每份资料、音色、授权和调用成本有归属；客户可单独停用，交付不串资料 |

顺序以“先完成可验证的体验和交付，再扩大能力”为准。真实人物素材、录音授权和服务开通是试点及声音复刻的外部输入；服务器与域名是长期交付的外部输入。动态形象单独验收，租户和批量管理按客户规模逐步建设，当前不提前重构。

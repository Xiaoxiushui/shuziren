# 录音与朗读故障修复（2026-11-08）

## 故障与定位

负责人反馈：在微信内置浏览器点击录音和朗读不可用，也没有可见提示。

实测原服务：`/api/asr` 返回 503，`/api/tts` 回退到浏览器朗读。直接检查阿里云 ASR、TTS，两者均返回 HTTP 400、`ACCESS_DENIED`，明确指向当前 Token 无效。微信中的备用朗读和麦克风能力不能假定存在，原来的提示也位于输入框下方，容易看不到。

负责人已在本机更新 `server/.env` 的 `NLS_TOKEN`。新配置的真实 TTS、ASR 联调通过，没有把任何凭据写入本记录。

## 已做的修复

- 录音的准备、授权等待、识别和失败状态显示在页面顶部；不支持录音或无法使用备用朗读时给出明确提示。页面脚本未能加载时也有可见提示。
- 在点击录音时立即创建、唤醒音频上下文，再等待麦克风授权；超时、取消和重置会释放上下文及迟到的录音流。
- 音频播放被 `NotAllowedError` 拦截时保留生成的音频，显示“点此播放”；再次点击直接播放，不重新请求合成。备用朗读被拒绝时也允许再次点击。
- 浏览器禁止本地存储时，仍在当前页面保留扫码口令；人物列表和页面跳转也传递口令。
- 一键启动的健康检查带上访问口令，并确认服务身份；局域网二维码和自动打开的页面带上口令。
- 新版服务会重读由 `.env` 提供的配置；后续更新文件中的 Token 无需再次重启。启动环境中的显式配置仍优先。

## 维护说明

控制台 Token 是临时凭据。当前实现支持更新本机配置后自动重读，但尚未实现凭据自动续期。长期调用应另接自动获取与刷新流程，参见[阿里云临时 Token 说明](https://help.aliyun.com/zh/isi/user-guide/obtain-an-access-token-in-the-console)。

播放重试按浏览器 `play()` 拒绝结果处理，不绕过播放限制，参见 [HTMLMediaElement.play()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)。

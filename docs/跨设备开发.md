# GitHub 与跨设备开发

GitHub 保存代码、文档、自动检查和两个虚构人物样例。当前本地真实模型配置不会随仓库上传；换设备后需要单独配置。

本项目仓库：[Xiaoxiushui/shuziren](https://github.com/Xiaoxiushui/shuziren)，主分支为 `main`。

## 第一次在另一台电脑开发

安装 Git、Python 3.13（服务使用标准库）、Node.js 24（只用于前端检查）。登录拥有仓库访问权的 GitHub 账号，从仓库的 Code 按钮复制 HTTPS 地址：

```text
git clone https://github.com/Xiaoxiushui/shuziren.git
cd shuziren
git switch main
```

Windows 可双击 `一键启动.cmd`，或运行：

```powershell
py -3 server/server.py --host 127.0.0.1 --port 4174
```

macOS / Linux：

```sh
python3 server/server.py --host 127.0.0.1 --port 4174
```

访问 `http://127.0.0.1:4174/`。如果要生成二维码，另安装可选依赖 `python -m pip install -r requirements.txt`（Windows 可用 `py -3 -m pip`，macOS/Linux 可用 `python3 -m pip`）。

首次运行默认是演示模式。需要真实服务时，复制 `server/.env.example` 为 `server/.env`，在本机填写模型和语音配置后重启。不要在聊天、提交或 issue 中粘贴密钥。真实人物的草稿、审核记录、原始素材和版本归档需通过自己认可的私有渠道另行迁移；GitHub 不同步它们，仅复制人物 JSON 不足以启用真实人物。

## 每次换设备的顺序

离开设备前提交自己的改动并推送；到另一台设备先拉取。多人或多设备独立工作时使用不同功能分支：

新设备第一次提交前，在仓库目录设置提交者身份（可使用 GitHub 设置中显示的 noreply 邮箱）：

```text
git config user.name "你的姓名或 GitHub 用户名"
git config user.email "你的 GitHub 提交邮箱"
```

```text
git switch main
git pull --ff-only origin main
git switch -c codex/你的功能名称
# 编辑代码，执行下面的检查
git add 具体修改的文件
git commit -m "说明这次改动"
git push -u origin HEAD
```

在 GitHub 创建 Pull Request，检查通过后合并。另一个设备从 main 拉取合并后的代码。已有工作区先用 `git status` 确认未提交改动；不要用强制推送覆盖另一台设备的工作。

## 本地和云端检查

在 Windows 用 `py -3`，macOS/Linux 用 `python3` 替换下面的 `python`：

```text
python -m unittest discover -s tests -p "test_*.py" -v
node --experimental-vm-modules --test tests/*.test.mjs
python scripts/manage_profile.py check --all
```

仓库的 `.github/workflows/check.yml` 会在推送、PR 和手动运行时，于 Windows 与 Ubuntu 执行检查。测试使用虚构夹具和本机假供应商，不需要在 GitHub 配置真实模型或语音密钥。首次上传后，以 Actions 页面实际运行结果为准；本地通过不等于云端已经通过。

## 只下载运行，不做开发

- 下载源代码：GitHub 仓库 → Code → Download ZIP。解压后按上述命令启动。ZIP 没有 Git 历史，后续更新需重新下载；持续开发请使用 clone。
- 下载经过检查的演示包：仓库 → Actions → 最近一次成功的 Check and package → Artifacts → `digital-memorial-demo`。解压下载件，再解压里面的交付 ZIP。构建件保留 30 天，过期后重新运行工作流或本地打包。
- 本地打包：`python scripts/package_demo.py --out out/digital-memorial-demo.zip`；单客户加 `--profile 人物ID`。

私有仓库及其下载需要有权访问的 GitHub 账号。代码托管不等于网站部署；上传仓库后不会自动生成公开 H5 网站。

## 手机使用

文字问答可按《手机访问交付》使用同一 Wi-Fi 的局域网地址。手机麦克风录音要求浏览器的安全上下文，普通局域网 `http://电脑IP` 通常不能使用录音；远程或真机语音测试需另行提供 HTTPS 地址和麦克风权限。本机 `localhost` 的录音结果不能替代 iPhone Safari / 微信内置浏览器的真机验收。

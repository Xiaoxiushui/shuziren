# 量产架构与阶段性目标

更新日期：2026-11-04　｜　状态：蓝图，尚未实施

> 2026-11-08 接手注：本文保留阶段蓝图及原始验收清单，不代表最新完成状态。真实 ASR/TTS 已有联调记录，iPhone Safari 已有跑通记录；当前进度、剩余验证和优先事项以《[接手梳理](接手梳理.md)》为准。本文中的供应商配额、价格和办理时间是历史规划参考，实际选型时需重新核实。

本文回答一个问题：**这个东西怎么从"一台电脑演示"变成"很多客户各自一份、批量生产"。**
当前阶段的真实目标只有一个——**把 demo 跑通**。本文件把这条线划清楚，免得为了将来的规模提前改坏现在能跑的东西。

---

## 一、阶段划分与边界

| 阶段 | 目标 | 客户数 | 要不要改架构 |
| --- | --- | --- | --- |
| **本阶段（进行中）** | demo 跑通：真实语音识别 + 真实语音合成 + 手机实测 | 0（演示人物） | **不改** |
| 试点 | 接 1–10 个真实客户，验证交付流程 | 1–10 | 只加两样 |
| 量产 | 客户自助导入资料即可生产 | 几十–几百 | 补全四层 |
| 规模运营 | 超过单账号音色上限 | 1000+ | 多账号分片 |

**本阶段明确不做**：租户体系、计量系统、自助导入后台、多账号路由。这些在 10 个客户以内都不是瓶颈，现在做只会拖慢 demo。

## 二、先纠正一个前提

**客户永远不需要、也不应该拿到 API 密钥。** 密钥是平台方的成本项，存在服务端，客户只看见网页。

所以真正的问题不是"每个客户配一个 key"，而是：**一个平台账号要同时服务很多客户，怎么把资料、音色、用量、授权分得清。**

## 三、阿里云侧的容量账（官方文档数字）

| 项目 | 数字 | 含义 |
| --- | --- | --- |
| 每账号自定义音色总数 | **1000 个**（声音复刻与声音设计共用） | 一账号最多服务 1000 位客户 |
| 创建音色 | 免费 | 创建不花钱，合成才计费 |
| 语音合成 / 实时对话 | 按目标模型用量计费 | 平台垫付，必须能算到客户头上 |
| 试用期并发 | 2 路 | 只够验证，量产必须单独购买并发与 QPS |
| 一句话识别 Token | **约 1 天过期** | 量产必须自动续期，不能靠人工 |
| 复刻音色绑定模型 | 创建时绑定 target_model，**不能跨模型用** | 换语音模型 = 客户音色要重建 |

## 四、量产要补的四层

### 1. 租户模型（最关键）

现在是平铺结构：`profiles/<人物ID>.json`。多客户后必须能回答"这份资料属于谁、谁审核的、用的哪个音色、这个月用了多少"。

建议目录形态（数据库实现另议）：

```
tenants/<租户ID>/
  profiles/     已发布人物资料
  drafts/       草稿
  reviews/      私有审核记录
  assets/       原始录音与授权材料（绝不外发）
```

约束沿用现有规则：**审核记录只走服务端，HTTP 永不返回，模型上下文里也不出现。**

### 2. 音色管理

- 每个客户一个复刻音色，统一挂在平台账号下，用创建时的 `prefix` 打客户编号
- 维护 `音色ID → 租户ID → 授权记录编号 → 绑定模型` 的映射表
- 三种生命周期必须处理：**配额用满要清理闲置音色、客户停止服务要下线、授权到期或撤回要失效**

### 3. 计量与限额

现在**没有任何用量记录**，这是量产最紧的缺口。

每条外部调用都要落一笔账：租户、类型（识别/合成/对话）、字符数或音频秒数、时间戳、是否回退。有了账才谈得上：单客户日限额、月度结算、成本核算、异常告警。

### 4. 密钥自动续期

平台持有一对长期密钥（AccessKey），服务端用它自动换取临时 Token 并缓存到过期前刷新。**这是量产的技术门槛，不是优化项。**

## 五、分期实施

**试点期（1–10 客户）—— 只做两件事**
1. 资料按客户分目录（现在是一个平铺的 `profiles/`）
2. 加用量日志（哪个客户调用了什么、多少次）

这两件事加起来几天，不做的话客户到第三个就开始乱。

**量产期（几十–几百客户）**
补：音色映射表、Token 自动续期、单客户限额、批量建档脚本（把"草稿→审核→发布"包成一条命令）。

**规模运营（1000+ 客户）**
才需要多账号分片：客户按音色归属分配到不同阿里云账号，服务端加一层"该客户的音色在哪个账号"的路由。

## 六、合规绑定（红线，不是建议）

- 每个客户必须留下**近亲属书面授权**，且授权记录与音色 ID 一一对应
- 授权到期或撤回 → 一键停用该人物 + 下线该音色，历史记录保留但不再能调用
- 页面上的"AI 生成"标识与"资料外不编造"的护栏**在任何租户下都不许摘**
- 原始录音、授权书只存服务端 `assets/`，不进 HTTP、不进模型上下文、不进交付 ZIP

## 七、本阶段的验收标准（demo 跑通的定义）

把下面这些做完，这一阶段就算完成：

- [ ] 阿里云"一句话识别"和"语音合成"开通试用，拿到 AppKey + Token
- [ ] 手机说一句话，页面把它转成文字，内容正确
- [ ] 页面把回答读出来，能听清、能停止
- [ ] **记录真实端到端延迟**：从按下录音到听见第一个字，实际多少秒（这是目前完全空白的数字）
- [ ] 断掉网络或密钥失效时，页面回退到浏览器朗读，不白屏
- [ ] iPhone Safari 与微信内置浏览器各测一次录音与播放
- [ ] 结果写入《验收记录》，并在《交接说明》更新状态

## 八、这一阶段不看、不碰的东西

- 口型驱动（需要独立显卡或云端 GPU，另立项目）
- 多租户改造（10 个客户以内不是瓶颈）
- 计量系统（等有第一个付费客户再说）
- 打断能力（等克隆音色跑通之后再评估，声音比打断重要）

## 九、公网演示与"固定二维码"的区别（2026-11-05 补充）

| 方案 | 地址稳定性 | 成本 | 适用 |
| --- | --- | --- | --- |
| 临时隧道 `scripts/share.ps1` | 每次重启都变，且依赖本机开机 | 免费 | 演示、给家人看一眼 |
| 固定域名 + 云服务器 | 长期不变 | 服务器几十到一百多/月 + 域名几十/年 | 把二维码印在纪念册、相框上 |

固定二维码的三件必需品：**固定域名、24 小时在线的服务器、数据存在服务器上**。国内还需 ICP 备案，审核 1–3 周——这是时间门槛，不是技术门槛。

两种方式代码完全相同，区别只在部署位置和入口。
